Django Recipe app

Project Overview

A responsive Django web application that allows users to explore, create, and manage recipes. This full-stack project demonstrates core CRUD functionality and user account management.
Users are able to:

  • Register and manage user accounts.
  • Browse recipes with detailed information including ingredients, instructions, prep/cook time, difficulty, and meal type.
  • Add recipes to their personal collection.
  • Search recipes by title or ingredient

Technologies Used

  • Python 3 / Django 5.2
  • Django Templates with HTML, CSS, and JavaScript
  • SQLite (development) / Heroku Postgres (production)
  • Pandas and Matplotlib for data analytics and visualization
  • Pillow for image processing
  • WhiteNoise for static file management
  • dj-database-url and psycopg2-binary for database configuration and connectivity
  • Django Widget Tweaks for enhanced form rendering
  • Django ORM for database interactions
  • Git & GitHub for version control and repository hosting
  • Heroku & Gunicorn for live app deployment

Objective

Develop a multi-user Recipe web application using the Django framework, allowing users to create, read, and modify recipes, search by ingredients, and manage content via an admin panel. The aim was to demonstrate and practice full-stack web development skills, including database integration with PostgreSQL, front-end rendering with HTML and CSS, deployment on Heroku, and best practices in coding, testing, and documentation.

The Experience

I personally found the Django framework with the “batteries included” to be more intuitive to work with, the MVT architecture simplifying the process by eliminating the need for a separate controller layer. I loved the “modular” feel of the structure with the project level files, the Apps, configuration files and database files. I was able to gain hands-on experience with models, forms, views, user authentication, static and media file handling, templating, URL routing, and deploying a full-stack Django app with PostgreSQL on Heroku. In terms of a full stack structure I found it refreshing that instead of wiring up a separate backend API and front-end client as per JavaScript frameworks like React and Angular, I was able to build, test, and deploy everything in one coherent environment. It made development feel more streamlined and productive.

The process included:

  • Create the app using Angular CLI
  • Implement user registration and login forms using Angular Material
  • Implement Angular components and define the app routing
  • Style the app using the React Bootstrap library
  • Comment the backend and frontend code using JSDoc and TypeDoc
