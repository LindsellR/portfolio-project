Django Bookstore app

Project Overview

A (hypothetical) bookstore Django web application for managing and viewing books and their sales records. Users can log in, browse a list of books, view details of each book, and check sales data. This is a sister project to the Django Recipe application.
Users are able to:

  • Login via username and password
  • Browse a list of books.
  • View details of a particular book by clicking on it's title link.
  • Access sales records of a book via book title search

Technologies Used

  • Python 3 / Django 5.2
  • Django Templates with HTML, CSS, and JavaScript
  • SQLite (development) / Heroku Postgres (production)
  • Pandas and Matplotlib for data analytics and visualization
  • WhiteNoise for static file management
  • dj-database-url and psycopg2-binary for database configuration and connectivity
  • Django Widget Tweaks for enhanced form rendering
  • Django ORM for database interactions
  • Git and GitHub for version control and repository hosting
  • Heroku and Gunicorn for live app deployment

Objective

Develop a hypothetical Bookstore web application in conjunction with the recipe application, as a test run, using the Django framework. The bookstore application provides information on books and is more focused for use by store owners or salespeople,managing content via an admin panel, and accessing sales records and data visualisation of sales.

The Experience

Building this app (in conjunction with the recipe app) with slightly different features than the recipe app (sales figures, customer lists, salespeople) gave an idea on how to build an app that could easily be user centric or both user and shop owner/operator focussed, but in this instance it is more focussed on keeping track of sales. My technical experience building this app is virtually the same as with the recipe app, gaining hands-on experience with models, forms, views, user authentication, static and media file handling, templating, URL routing, and deploying a full-stack Django app with PostgreSQL on Heroku.

The process included:

  • Creating and managing virtual environments
  • Creating Django project and apps
  • Creating Django models and database tables, defining views and urls
  • Adding database records using Django admin panel
  • Writing and implementingautomated tests
  • Using the Django admin panel
  • Setting up user authentication, login and logut features
  • Packaging Django application and deploying it on web server
